# NUTBUSTER — Premium Mobile Monetization Satire

NUTBUSTER is an offline-first, nut-themed match-three parody of predatory mobile monetization. The **player-facing fiction** sells exclusive bundles, hearts, gems, VIP status, and absurdly urgent offers as though purchases are inevitable. The joke must not be spoiled in onboarding or ordinary store copy: tapping BUY leads through a fictional offer review to a final checkout whose total is **FREE / $0.00**. All rewards are delivered without real payment. The app must not collect billing information or integrate purchase, advertising, tracking, or subscription SDKs.

Source/backup packs remain available in NUTBUSTER Google Drive. Fallback symbols are only used if a browser cannot load an installed image.

- **Nutvale Homestead:** 40 illustrated house tiers, 1,000 modular renovations, five estate grounds with 44 plots, 57 decorations, eight legacy prestige titles, and a playable **60-image illustrated human-avatar wardrobe** (40 progression outfits + 20 permanent seasonal costumes). Eight companions, five collectible sets, 19 achievements and preserved local saves remain supported. A further 20 goth/emo outfits are backed up in Google Drive but are not yet in the GitHub game.
- Shared deterministic match-three engine and 1,000 seeded main-campaign level configurations, including a 4×5 to 8×9 board progression, non-matching legal swaps, per-nut gravity/cascade traces, blocker layers, four usable boosters, persistent browser/device progress, satirical two-stage checkout, distinct victory/loss screens, and reward claims.
- Primary art is **the original five owner-generated glossy sprite sheets** from this project's design conversation. The sixth, labeled board reference sheet is supplementary only; it is not a replacement for the original art.
- 84 cropped sprites generated from primary art by `tools/prepare_assets.py` (source sheets can be downloaded in the separately provided asset archive). Board geometry uses runtime CSS edges until seamless corner patches are verified.
- Android native wrapper: minSdk **26**, compileSdk **36**, targetSdk **36**, matching verified ReverieVR `app/build.gradle` values as of 2026-10-20.
- Fire tablet target: **Fire OS 7 (API 28) and Fire OS 8 (API 30)** use the same Android WebView APK, local saves, assets and pinned signer. Every signed release now includes a separately named `NUTBUSTER-FireOS-tablet.apk` byte-identical to the Android APK for convenient sideloading. No Google Play Services are required. Fire OS 5/6 devices fall below `minSdk 26`; actual Fire hardware and Amazon Appstore acceptance remain unverified.
- Native desktop port: C++17/SDL3 builds genuine Windows and Linux game windows using direct sprite rendering and mouse input. Go browser launchers and Electron are removed from release packaging. The new SDL3 builds are **preview artifacts only**, pending feature parity. See [native desktop port](native/README.md).

## Run / test

Mining verification: `node tests/nutvale-mines-40-tier.test.js`, `node tests/nutvale-mines-ui-flow.test.js`, and `node tests/nutvale-economy-art.test.js`. Keep `node tests/nutvale-mines-design-lock.test.js` for the unchanged v1.0 non-equipment contract. The code includes the UI flow but the full Android and desktop distribution checks still need to be run.

Run `node tests/avatar-art.test.js`, `node tests/homestead.test.js`, `node tests/homestead-expansion.test.js`, `node tests/homestead-house-tiers.test.js`, `node tests/homestead-renovations.test.js`, and `node tests/homestead-ui.test.js` for estate persistence, cosmetics, achievement gating, and the two-stage $0.00 premium order. Run `node tests/engine.test.js` for 2,500 deterministic level/seed cases, including 2,500 scoring swaps, 2,500 non-matching swaps, and recorded fall-trace verification. Run `node tests/ui.test.js` for a dependency-free mocked-DOM smoke test of checkout, stable board rendering, match animation plumbing, and dedicated win/loss screens. These checks do not substitute for an actual Android/device rendering test.

Open `web/index.html` in a modern browser or run `python3 -m http.server 8000 --directory web` and visit `http://localhost:8000/`. For a native Windows/Linux desktop preview, follow [native/README.md](native/README.md); the Electron prototype is deprecated and must not be packaged. To make an Android debug APK, install JDK 17, Android SDK 36/build-tools and Gradle 9.6.1; `cd android && gradle :app:assembleDebug`. APK output is `android/app/build/outputs/apk/debug/app-debug.apk`. Verify on an API 26 device and a modern Android emulator.

The source includes Gradle wrapper configuration but not the wrapper JAR. Local builds can use installed Gradle 9.6.1; **GitHub Actions now provisions Gradle 9.6.1, SDK 36, JDK 17 and the build requirements automatically**. See `.github/workflows/build-and-release.yml`. Main-branch pushes build Android debug APKs and run Android emulator checks. Native Windows/Linux SDL3 preview builds run separately in `.github/workflows/native-desktop-preview.yml`. Signed APK publication uses NUTBUSTER-owned GitHub repository secrets, not the ReverieVR signing handoff. The only permitted Android publisher is the dedicated NUTBUSTER certificate pinned in `config/nutbuster-publisher.sha256` (cdde49a6d72b49e50d1cf3454ebb0a1e63444640719e4afa40c6c74bd5c8b0b9). `bash scripts/setup-nutbuster-signing.sh` ONLY re-uploads the previously generated NUTBUSTER key from the local encrypted keystore; it will not create a replacement. Back up that existing keystore and password privately. Build and Gradle release validation reject a different signing identity. ReverieVR signing must never be used for NUTBUSTER releases. Existing Android apps signed with the old ReverieVR identity cannot be updated in place with the NUTBUSTER key; Android enforces this without exceptions. Do not uninstall a device install that contains important unsynced progress without first deciding how to preserve it. Debug keys are never substituted. The native Android app **does not** check for updates automatically, download APKs, request package-install permissions, or install anything. The Settings **GET LATEST APK · GITHUB** button opens the public GitHub Releases page in the device browser. Players download the newest published `NUTBUSTER-Android-phone-test.apk` and let Android's normal Downloads/file installer handle the update; they should update over the existing installation to preserve local progress. The APK retains the pinned NUTBUSTER signing identity and increasing version codes. Debug builds are not in the signed release lineage. The old Go Windows browser launcher is deprecated and no longer packaged or published. Windows/Linux native SDL3 preview ZIPs are supplied separately until full gameplay parity is complete.

## Invitations, local progress, and account policy

Players can select **INVITE FRIENDS** from the home screen, Nutvale Homestead, or Settings. Android uses the system's share chooser to send the public [NUTBUSTER releases page](https://github.com/mrcalzon02/NUTBUSTER-R/releases) to compatible installed apps; web/desktop uses Web Share or a copy-link fallback. Sending an invitation does not require Facebook login, contacts access, social IDs, or a new service. Receiving players must choose, download, and install the release themselves; the invitation is not multiplayer.

Progress, avatar selection, homestead inventory, and earned prestige are stored on the current installation. There is no NUTBUSTER cloud saving, linked account identity, or cross-device syncing. Android automatic backup is disabled. GitHub receives ordinary browser/network metadata only when the player elects to open the Releases page, and the chosen social network receives any link the player explicitly shares.

Later social profiles/prestige plates may use privacy-reviewed **read-only, self-contained share links** hosted by a static page rather than a player database. See `docs/wiki/Social-and-Prestige-Sharing.md`.

**Post-1.0 only:** Google Play App Bundle publishing, a compliant Play-specific update channel, optional Play Games achievements and cloud saves, Facebook/social exports, and possible online homestead visiting are staged in [`docs/wiki/Post-1.0-Platform-Roadmap.md`](docs/wiki/Post-1.0-Platform-Roadmap.md). The manual GitHub release-link workflow and Android package/signing remain unchanged, while Windows/Linux move to native SDL3 previews until verified gameplay parity; this plan does not authorize external SDKs or require player accounts.

## Art asset import

To generate the full art pack, copy five original sheet PNGs into `assets/source/` retaining filenames, then run `python -m pip install Pillow` and `python tools/prepare_assets.py`. The build automatically includes any `web/art/primary/` files. Without them, puzzle pieces degrade to readable fallback symbols rather than crashing. **The original full-resolution sources and 84 generated assets are included in the accompanying starter ZIP. The GitHub repository also includes 34 compact 96-pixel variants** from those primary sheets so the core game renders the actual art immediately. Import the full-res PNGs and regenerate when production-ready.

## Production scope / known limitations

This alpha is a functional vertical slice, not a final content-complete match-three release. The boards are seeded procedural shapes, not 500 bespoke tuned puzzles. Special nut combinations, diverse objective types, advanced blockers, and device-specific animation and layout quality still require implementation or balance testing. Currency grants and unlocks are local to each installation. The three-hour chest tracks a local cooldown, while immediate opening remains accessible. VIP and currency remain offline. Final checkout reveals a zero-dollar price; no payment credentials are requested.

## Mandatory APK release compliance gate

Every Android release test must include the [38-control release checklist](docs/APK_RELEASE_COMPLIANCE_GATE.md) and the release-blocking `tests/apk-release-compliance.test.js` functional check. This test validates policy-checklist presence and evidence-validator integrity only, never Play Console approval or device certification. For release signoff use `python3 tools/verify_apk_release_gate.py --evidence <manifest.json> --apk <signed.apk>` plus real signature/upgrade/console evidence. The development GitHub sideload channel stays active on `main`; the parked `google-play` branch has a separate stricter candidate gate and must not publish through the sideload signer. 

## Native desktop development

Windows/Linux desktop game targets use C++17, SDL3 and approved source sprites: **no Chromium, Electron, browser, WebView, or local server**. The old browser-based launchers are no longer part of new signed releases. Native desktop previews are built in `.github/workflows/native-desktop-preview.yml`; they do not yet implement the complete mobile game. See [native/README.md](native/README.md) for progress and missing systems.

## Required four-target feature development

Every gameplay addition or revision is an Android, Fire OS, Windows **and** Linux development item. The two implementations are the shared Android/Fire OS APK and the native Windows/Linux C++17/SDL3 executable; neither is silently substituted for the other. [Cross-platform development and release-line rules](docs/wiki/Cross-Platform-Feature-Parity.md) are enforced by `config/platform-parity.json`, `tools/platform-parity.js`, and native CI that runs whenever `web/**` gameplay changes. Desktop downloads remain **preview-only** until feature parity is verified; the signed Android/Fire OS publisher remains independent of unfinished desktop work.
